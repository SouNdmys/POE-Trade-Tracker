# C · UI 状态与视觉层级评审（1.0 发布前）

评审对象：`crates/ptt-app/src/shell/`（11 个页面模块 + HUD + 全局 chrome），依据
`docs/UI-DESIGN.md`、`README.md`、`i18n.rs` 文案目录与源码 grep；未构建、未运行。
只看了 `docs/poe2-ui/project/uploads/` 里两张**重设计前**的应用截图（雷达页、关注列表页），
用来确认信息骨架（左导航栏 / 顶部监视带 / 底部状态行 / 右侧明细栏），不用来评现版排版。

页面清单（`shell/pages.rs`）：监视器 monitor · 校准 calibrate · 雷达 opportunities
（抓取雷达 / 交易所雷达两页签）· 兑换 convert · 关注列表 watchlist · 历史 history ·
市场分析 analytics · 交易所 exchange · 设置 settings（基本 / 浮窗 / 赛季与存储 season /
算法参数 tuning）· 浮窗 HUD · 全局 chrome（顶部监视带 + 底部状态行）。

## 2. 问题清单（按影响权重排序）

### Blocker

**B1 · 交易所同步失败在界面上没有落点，空状态还许了一个可能兑现不了的承诺**
现象：`exchange_sync.rs` 里同步出错只 `push_log("exchange: {error}")`，这行英文进底部状态行，
下一条日志一来就没了；`exchange.rs` 页面本身不读任何错误字段（grep 无 `exchange_error`）。
同时空状态文案 `exchange_no_data` 写的是「还没有交易所数据——同步几分钟内会自己补齐」。
联赛名是用户手填的（用户实际要改成 Allflame），拼错一个字母、API 限速 429、断网，
三种情况在页面上长得一模一样：一句「几分钟内会自己补齐」+ 「落后 N 小时」的数字越来越大。
为什么在意：这是用户唯一会去核对「我填的联赛名对不对」的地方，而它永远不会说「不对」。
严重程度：**Blocker**。修法在页面上加一行「上次同步失败：<原因>」+ 让 `exchange_no_data`
在连续失败后换句话即可。

### Should-Fix

**S1 · 全局 chrome 不显示当前是 POE1 还是 POE2、联赛是哪个、赛季是哪个**
现象：顶部带只有 呼吸点 / 监视中 / 已接受 N / 已跳过 N（`mod.rs` 2185–2235），左导航只有页名。
1.0.7 已做 POE1 对齐，用户两个游戏都在用；切错档案时，雷达、兑换、交易所的每个数字都还是
「看起来对」的。交易所页的同步行也只有时间不带联赛名。
为什么在意：这是「全凭记忆」类信息里代价最高的一条——错档案不是显示问题，是拿错市场做决策。
严重程度：**Should-Fix**（用户实际两游戏切换时应视为 Blocker）。

**S2 · 后台加载失败以「故障: <Rust 错误原文>」当空状态显示，样式与「—」相同**
现象：`report_body()` 把 `PageData::Failed(reason)` 渲染成 `"{fault_prefix}: {reason}"`，
走 `empty_state()` 灰字；`reason` 是 `storage: …` 之类的英文原文，中文界面也是英文。
六个页面（雷达 / 兑换 / 关注 / 历史 / 分析 / 交易所）共用这条路径。
为什么在意：一次 SQLite 锁冲突或迁移失败，用户看到的是和「没数据」同色同位置的一行小字。
严重程度：**Should-Fix**。至少改成 `DANGER_TEXT`，并给最常见的两三类错误配人话。

**S3 · 关注列表页没有任何「多久前」**
现象：行内只有「每个 ≈ 46.37 混沌石（两侧）」；两侧/单侧/没抓到 说的是覆盖度，不是新鲜度。
右栏「覆盖与缺口」的「两侧报价都缺」标签同样没时间。
为什么在意：README 说这页回答「whether it is healthy」；一个三天前的 46.37 和一分钟前的
46.37 在这页无法区分，而其余五个数据页都做了新鲜度。
严重程度：**Should-Fix**。

**S4 · 兑换页的核心结论没有数据时间**
现象：顶部结论带「100 神聖石 → 最多 19 · 比直兑多 9 · 最好那条只吃得下 14」和表格每行的
收益 / 深度条都没有「抓取于 N 分钟前」；只有点进一行后，明细里每段各一颗新鲜度点。
为什么在意：这页是用户真正下手交易前看的最后一页；过期路线和新鲜路线在表里同款同色。
严重程度：**Should-Fix**。

**S5 · 百分比有三套格式化，±999 截断只有交易所页有**
现象：`reports.rs::percent_from_bps` = `{:+.2}%`（永远带符号，浮点）；
`report_text::percent_from_basis_points` 不带正号、整数算；`exchange.rs::signed_percent`
再补正号并截断到 `>+999%`。结果：雷达收益「70.22%」无号，监视器 / 交易所「+50.00%」有号。
开服头几天以稀缺锚计价的涨幅能到几千万个百分点（交易所页注释原话），雷达 / 分析 / 兑换
的百分比没截断，会撑破 28px 单行硬约束。
严重程度：**Should-Fix**。收口成一个函数、一个签名规则、一处截断。

**S6 · 大数字两套口径：市场分析用「万」，交易所用 k / M**
现象：`analytics.rs::wan()` → `1214万`；`exchange.rs::compact_amount()` → `125k` / `3.5M`。
两页相邻、量纲相同（成交量 / 供需量）。且 `万` 是硬编码中文，English 界面下也是 `1214万`。
严重程度：**Should-Fix**（小改）。

**S7 · 主窗口没有最小尺寸**
现象：`lib.rs` 只给了 `WORKBENCH_SIZE` 初始尺寸；所有列宽预算按 1280×800 定
（`UI-DESIGN.md` §1.4、§3），无 `min_size`。缩到 1100 以下时固定列宽表格会被右栏挤压。
严重程度：**Should-Fix**（一行配置）。

**S8 · 「已排队」与 "pinned" 说的不是同一件事**
现象：`pinned_label` 中文「已排队」、英文 "pinned"。待抓队列里混着两种条目：系统建议的
（抓一次就消失）和用户钉住的（sticky，抓完也留着）。「已排队」描述不出「抓完还在」这个差别，
而这正是用户要记住的规则。
严重程度：**Should-Fix**（改一个词，如「常驻」/「钉住」）。

**S9 · 兑换页隐藏了「汇率比直兑差」的路线，但不说隐藏了几条**
现象：只有一条都不剩时才出 `no_route_beats_direct`；正常情况下用户看不到「已隐藏 N 条」。
为什么在意：用户在游戏里看到一条路线，回来这页找不到，分不清是被隐藏了还是没抓到。
严重程度：**Should-Fix**（表尾一行计数）。

### Nice-to-Have

**N1 · 刷新期间无进行中标记**
`PageData::Loading` 只在首次加载出现；「刷新」按钮（兑换 / 历史）点下去页面直接在新旧数据间
切换，无 busy 状态。目前查询快，看不出来；赛季页已经因为「卡一下」修过一次同类问题。

**N2 · 底部状态行 = 最近一条日志**
无时间戳、无级别、无历史，一条盖一条。`self.fault` 之外的所有非致命错误（交易所同步、
热键占用）都只在这里闪一下。要么升级成可展开日志，要么把这 22px 换成固定信息（见 S1）。

**N3 · 三处绕过了文案目录的编译期双语强制**
`state.rs::loading_label`、`mod.rs::skip_label` 用内联 `match language`，
`settings.rs:714` 客户端语言 chip 硬编码「繁中」（English 界面下也显示中文）。
README 承诺「少一种语言就编不过」，这三处不在保护范围内。

**N4 · 汇率写法三种并存**
雷达「1 : 8.7224」（四位）、市场分析 / 关注「每个 ≈ 26.98」（两位）、`reports.rs::ratio_display`
（≥100 无小数，否则三位）。§6 已裁定「每个约 X」，雷达 / 兑换未跟。

**N5 · 雷达「可执行性」「风险」两列在数据稀薄期全表同值**
重设计前截图 12 行全是「数据不够」+「流动性薄」；现版压成 4 字徽章但仍每行重复。
一列所有格子相同就没有信息量，可折进事实带一句「N 条数据不够」。

**N6 · 定价锚只在市场分析顶栏和关注列表出现**
雷达 / 兑换 / 交易所页内不显示「以什么结算」，改了结算通货后这三页的数字换了口径但页面不说。

**N7 · 市场分析「截至」只到日，没说这是日粒度**
`as_of_day` 是日 rollup，合理；但和其它页面「N 秒前」的口径并列时，用户会以为它也是实时的。

## 3. 已达交付标准的亮点

1. **监视器健康带 + HUD 三态**：红黄绿被新鲜度独占并写进硬约束；跳过时「数字降灰不抹掉 +
   8s 前」，「已跳过 566」拆成「正常待机 549 / 真跳过 17」并有回归测试守着。这是整个应用里
   过时状态做得最完整的地方，不必再动。
2. **空状态带路径**：历史页「已有 12 根，24 小时需要 288 根」、市场分析「还差 N 天」、
   校准页「2 / 3 · 还差交易表格」、交易所页把「未配联赛 / 回补中 / 真没数据」拆成三句。
   每一句都告诉用户下一步做什么，而不是一个横杠。
3. **更新器**：一个枚举管四个阶段、三段不同单位的进度、12 条具体错误文案、
   「已装好 v1.0.8，重启后生效」带版本号。作为设置页里的一个角落，成熟度高于主流程。

## 4. 建议裁减

1. **雷达「可执行性」+「风险」两列**（约 170px）：数据稀薄期全表同值，数据充足期又大多为空
   （§6「没标签就是没事」）。折进事实带 + 明细栏，把宽度还给路径列（§3 已经在为路径列抠 12px）。
2. **`tuning.convert_sizes = 1,10,100`**：§7 已将其降级为「没填持仓时的默认候选」；若兑换页
   总是要求填持仓，这项就是 24 个算法参数里的一个僵尸项，连带它的单位换算与还原逻辑。
3. **底部状态行「最近一条日志」**：无时间戳、无历史、会被覆盖，实际承担不了报错落点（见 B1、N2）。
   要么补成真正的日志面板，要么撤掉换成 S1 需要的固定信息，不要停在中间。
