# 评审 B：「盲目自信」的错误输出（1.0 发布前）

评审日期 2026-09-02。范围：工具在输入出错（OCR 误读、网络失败、补丁改名、脏数据、
本地损坏）时，界面会不会**若无其事地显示一个错的数**。不修代码、不提新功能。
判定纪律：错误被吞掉、拿默认值/旧值/零值继续算并正常显示 = Blocker。

已知未修项（`docs/P10-FOLLOWUPS.md`）不重复列，除非它本身够 Blocker。

## 一张表：场景 × 用户看到什么 × 能否分辨

| # | 场景 | 用户端看到什么 | 能否从界面分辨 |
|---|---|---|---|
| 1a | OCR 把物品名认错成**目录外**的字 | 帧被跳过，Monitor 页 skip 计数 `need-name`/`have-name` 带原文 | 能（有原因、有原文） |
| 1b | OCR 把名字认成**目录内另一个**通货（如漏掉「完美」前缀） | 一本正常的书落到错的交易对下，各页正常显示 | **不能** |
| 1c | 汇率少读/多读一位、1↔7 | 破坏本侧单调序的行被点名剔除；**不破坏序的误读**（首/末行、7.5 vs 8）原样入库 | 单行剔除可见；保序误读不能 |
| 1d | **库存**数字少读/多读一位 | 直接进入深度、覆盖度、流动性档位，显示正常 | **不能**（库存没有任何合理性约束） |
| 1e | 只读到半个弹窗 | `RowsReject::*` / `EmptyBook` / `BookNotOnScreen` 跳帧，skip 可见 | 能 |
| 2a | 官方 API 超时/429/5xx | 底部状态栏一行 `exchange: fetch …`，30 秒后重试；页面继续用旧水位 | 数据小时/「落后 N 小时」可见；**失败原因只在会被覆盖的单行日志里** |
| 2b | 某小时被 CDN 回成「空市场」且距今 >3h | 永久写 mark，此后永不重访 | **不能**（永久空洞，趋势悄悄偏） |
| 2c | 某小时 JSON 永久解析失败 | 每 30 秒同一条错误刷一遍，水位不前进，回补全部停摆 | 落后小时数会一直涨；原因只在日志行 |
| 3a | 补丁改名，目录没有 | 同 1a，永远跳帧；关注/覆盖页继续催「去抓 X」 | 能看 skip，但「为什么老抓不到」要自己推 |
| 3b | 价格一夜 ×10 | 单书内中位带不跨时间，不会把真涨当噪声；API 趋势扣市场中位漂移 | 大体能（有 RateSpike/RateDrop 旗标） |
| 4a | API 返回小数/缺字段/负数 | `parse_hour` 报错 → 走 2c | 同 2c |
| 4b | API 返回零成交量 | 大雷达过滤（`volume==0` 剔除） | 能（无输出） |
| 4c | OCR 两本互相矛盾的书 | market-book 每 context 只选一本自洽书，落选原因可见 | 能 |
| 5a | `settings.json` 损坏 | **静默回到出厂默认**：标定区域、联赛名、关注名单、热键全没了；下一次保存把坏文件覆盖掉 | **不能**（和「第一次启动」长得一模一样） |
| 5b | 数据库打不开/损坏/被锁 | 页面 `PageData::Failed` 带 `fault_prefix`；抓取写失败 → 红色状态栏并停止监视 | 能 |
| 5c | 数据库能开但 pulse 读失败 | 结构注记（「结构性薄流动性」等）**静默消失**，页面其余正常 | **不能**（和「还没历史」一样） |
| 5d | 日 rollup 失败 | `let _ =` 吞掉，Analytics 少几天，紧接着 prune 照跑 | **不能** |

## 问题清单（按影响权重排序）

### B-1  settings.json 损坏时静默回到出厂默认，并在下一次保存时覆盖原文件
**具体现象**：`SettingsStore::load` 把「文件不存在」和「JSON 解析失败」都归成
`LoadStatus::Defaults`（`crates/ptt-settings/src/lib.rs:782-816`）；shell 只取
`loaded.settings`，`loaded.status` 直接丢弃（`crates/ptt-app/src/shell/mod.rs:556-557`）。
启动即 `let _ = store.save(&settings)`（`mod.rs:598`，热键归一化时触发），之后任何设置改动
也会 `save` —— 原来那份损坏但可能大部分可救的文件被出厂默认覆盖。
**为什么用户会在意**：标定区域没了 → OCR 全帧跳过或读错位置；联赛名没了 → 同步整轮跳过；
关注名单/结算通货没了 → 雷达与兑换页按默认锚算。界面上全部表现为「像新装的一样」，
用户不知道是文件坏了，也没有备份能找回。写坏文件的场景并不罕见（崩溃时半写、杀毒软件、
磁盘满）。文件头注释自称 crash-safe，但那只保证**写**是原子的，**读坏了怎么办**没有答案。
**严重程度**：**Blocker**。
修法在三行内：`Err(_)` 分支先把原文件 rename 成 `settings.json.corrupt-<时间>`，
再返回一个新的 `LoadStatus::Corrupt`；shell 把非 `Loaded` 状态 `push_log` 一句并置 `fault`。

### B-2  库存数字没有任何合理性约束，误读直接进入深度/覆盖度/流动性档位
**具体现象**：汇率有单调序不变量（`crates/ptt-recognition/src/book.rs:60-110`）和
中位离群带（`crates/ptt-market-book/src/lib.rs:828-860`），库存只有 `NoStock`
（=0，`lib.rs:766-767`）一条。双读确认（`crates/ptt-monitoring/src/session.rs:160-210`）
要求两帧签名一致，只挡闪烁，不挡稳定误读。一个 `1855` 被读成 `185` 或 `18550`，
会原样进入「市面挂着 X，这一趟要吃掉 Y（Z%）」、`LiquidityClass`、雷达的搁浅比例排序。
**为什么用户会在意**：项目的核心裁定是「流动性 > 汇率」，库存正是排序的第一键；
一次误读能把一条路线从「吃不满」推到「可执行」，或反过来。Monitor 页确实显示最近一本书
的行，但用户不会逐行对着游戏核对。
**严重程度**：**Should-Fix**（高）。不到 Blocker 是因为它是输入错误而非吞错误，
且 Monitor 页留有原始行可核对。可行方向：同侧库存相对中位数的粗带（10×）旗标而不剔除。

### B-3  同名前缀通货被认成另一个，书静默落到错的交易对
**具体现象**：名字解析是精确匹配、禁止模糊（`crates/ptt-recognition/src/identity.rs:1-5`），
这挡住了「认成目录外」；但目录里存在只差一个前缀的对（崇高石 / 完美崇高石，混沌石 /
完美混沌石），弹窗只读到半个时前缀丢失仍是一个合法命中。没有任何跨帧校验
「这本书的汇率量级和这对通货的历史像不像」。
**为什么用户会在意**：完美 vs 普通差一个数量级；书落错对之后，估值、雷达、兑换页
都会拿它当真实观测，而且它还会**污染历史**（日 rollup、pulse）。
**严重程度**：**Should-Fix**。证据是结构性的（identity.rs 的设计边界），没有实机复现。

### B-4  pulse 读失败时结构注记静默消失
**具体现象**：`load_pulse` 全部 `.ok()?`，任何存储错误都返回 `None`
（`crates/ptt-app/src/shell/mod.rs:1706-1723`），文档注释明说「annotations simply stay
absent, the page itself is unaffected」。Watchlist/Convert/Opportunities 拿到 `None`
后照常渲染，只是少了「结构性薄流动性」「价值趋势」这类**警示**。
**为什么用户会在意**：注记消失的方向是**让路线看起来更安全**——少一条警告，
不是多一条。用户无法区分「这对确实没结构性问题」和「今天数据库读挂了」。
**严重程度**：**Blocker**（按纪律：吞错误 + 默认值 + 正常显示）。实际影响中等，
但修法在三行内：`load_pulse` 改返回 `Result`，错误串放进模型的 `notes`，页面已有 note 渲染通道。

### B-5  「>3 小时的空小时永久标记为空」会把 CDN/发布延迟固化成永久空洞
**具体现象**：`exchange_sync.rs:272-283` 对 `markets.is_empty()` 的小时按
`classify_empty` 判定，超过 3 小时即 `replace_exchange_hour(…, &[], …)` 写永久 mark；
`CORE-TRADING-MODEL.md:1307-1308` 自述「踩错这条会留下永久空洞，趋势悄悄偏」。
实测 API 延迟本来就是 1–2 小时（记忆笔记），补丁日/维护日延迟超过 3 小时并不稀奇；
CDN 故障回 200 + 空数组同样命中这条。
**为什么用户会在意**：小时账本、日线、7 天趋势、大雷达都建立在这些小时上；
一个洞不会报错，只会让当天成交量偏低、趋势偏斜，而且**永不自愈**。
**严重程度**：**Should-Fix**。方向：把「确认为空」改成可过期的软标记（例如 24 小时后
允许重访一次），或至少在 Exchange 页显示「本窗口内有 N 个确认空小时」。

### B-6  同步失败只有一行会被覆盖的日志，没有页面级「上次同步失败」状态
**具体现象**：所有同步错误（fetch/parse/store）走 `push_log(format!("exchange: {error}"))`
（`exchange_sync.rs:114-117`）；底部状态栏只画 `self.log.back()`
（`mod.rs:2288-2296`），下一次抓到书的 headline（`mod.rs:950-952`）或账本计时行
（`mod.rs:1153-1156`）就把它顶掉。永久性错误（B-5 的解析失败、某小时 404）每 30 秒
重试一次（`exchange_sync.rs:120-127`），无退避、无上限、无「已连续失败 N 次」。
**为什么用户会在意**：数据年龄本身是可见的（雷达头「数据小时 X（落后 N 小时）」
`report_text.rs:187`，Exchange 页每分钟刷新的落后数 `mod.rs:862-871`），所以用户能看到
「落后了」，但看不到「为什么」和「多久了」；表现和「GGG 还没发布」完全一样。
**严重程度**：**Should-Fix**。

### B-7  日 rollup 失败被 `let _ =` 吞掉，prune 紧接着照跑
**具体现象**：`mod.rs:1676-1689`：`ensure_daily_rollups` 与 `prune_raw_days` 的结果都被
丢弃，且 prune 不以 rollup 成功为前提。注释自述「degrades to less history」。
**为什么用户会在意**：Analytics 与 pulse 少几天没有任何提示；更糟的是若 rollup 因
（例如）某天数据触发 `StorageError::Rejected` 而失败，而那天已超出 `raw_retention_days`，
prune 可能删掉从未折叠过的原始书——**未验证** prune 是否检查 rollup mark，需要确认。
**严重程度**：**Should-Fix**（若 prune 不查 mark，则升为 Blocker）。

### B-8  赛季读取失败被当成「没有赛季」，窗口不再钳制
**具体现象**：`load_window` 里 `store.active_season(...).ok().flatten()`
（`mod.rs:1644-1647`），`exchange_sync.rs:206` 同型。读失败 = 无赛季 = 窗口不钳制，
上季数据可能混进本季页面。
**为什么用户会在意**：跨季混书正是 P10 特意用「换季 = 钳制归档」防住的事；
一次读错就把这道门悄悄打开。
**严重程度**：**Should-Fix**（低）。触发概率低，但方向是错数据而不是缺数据。

### B-9  汇率保序误读不可检测
**具体现象**：`out_of_order_rows` 只能抓破坏单调序的行（`book.rs:73-80`）。首行 `1.5`
读成 `7.5` 而次行是 `8`，序不破、中位带（≥3 行才启用）也不一定越界，原样入库并成为
「首档汇率」——而首档汇率是兑换页与雷达页的利润基准（`CORE-TRADING-MODEL.md:627,871`）。
**为什么用户会在意**：首行就是所有利润百分比的分子。
**严重程度**：**Nice-to-Have**。OCR 的固有边界，没有廉价的程序性解法；
列出来是让作者知道这条线在哪。

### B-10  补丁改名后的通货「永远抓不到」没有归因提示
**具体现象**：目录外名字 → `NeedNameUnresolved{text}` 跳帧（`route.rs:20-27`），
skip 原文可见；但关注页/覆盖缺口页继续把该对列为「去抓」，两页之间没有连线。
**严重程度**：**Nice-to-Have**。原因可见，只是要自己拼。

## 已达交付标准的亮点

1. **OCR 识别层是 fail-skip 而不是 fail-guess**：名字精确匹配、禁模糊（`identity.rs`）；
   双读确认（`session.rs`）；行序不变量点名剔除单行而不是整帧作废（`book.rs`）；
   每侧中位离群带 + 每条落选行带原因（`ptt-market-book` `QuoteRejectReason`）。
   这是整个工具最结实的一层。
2. **页面读失败会大声说**：六个 loader 的 `Err` 全部落到 `PageData::Failed` 并带
   `fault_prefix`（`mod.rs:1383,1515-1552`）；抓取写失败 → `UiEvent::Fault` → 红色状态栏
   并停止监视（`mod.rs:959-962`）。数据库锁/损坏/磁盘满不会产出静默错数。
3. **API 摄入是强类型的**：小数/缺字段/负数都在 `parse_hour` 报错
   （`ptt-exchange-history/src/lib.rs:170-171,322`）；零成交量在大雷达被剔除
   （`exchange_radar.rs:112`）；联赛名写错会被识别并把数据里的真名摆出来
   （`exchange_sync.rs:160-172`）。

## 建议裁减

- **`LoadStatus` 的三态枚举目前没有任何消费者**（`mod.rs:557` 丢弃）。要么接上
  （B-1 的修法），要么删掉——一个看起来有「未来 schema 只读保护」而实际上没人读的状态，
  比没有更容易让下一个人误以为已经防住。
- **账本计时行不该占状态栏**（`mod.rs:1153-1156` 「ledger N hours / M rows in K ms」）。
  它是性能探针的信息，却会顶掉同步错误那一行。放进 probe 输出即可。
- 30 秒无退避重试（`exchange_sync.rs:120-122`）：对永久性错误只是稳定地制造噪音，
  改成「连续失败 3 次后退到整点」比现在更诚实，也更省 CDN。
