# P1 标定笔记 — POE2 zh-TW @ 2560×1440 视窗全屏

来源：`test-screenshots/`（24 张，2026-08-15，Vulkan + DLSS 品质档，界面亮度 +0.5）。
首张样本（15.03.32.74，神聖石↔混沌石）实测：

## 文本极性（重要修正）
肉眼看似"羊皮纸浅底深字"的交易表，实际像素是**中灰底 + 暖米金亮字**：

| 区域 | 背景 | 文字 | 结论 |
|---|---|---|---|
| 可用/競爭交易表正文 | 灰 (60-95,60-90,45-75)，L≈60-95 | 暖米金 ≈(204,185,143)，L≈180-205 | BrightOnDark，相对亮度阈值 ~L140 分离干净 |
| 表头条（比率/庫存 行） | 更亮 ≈(150,135,105) | — | 排除在行带区外，或作锚点条 |
| 通货名称槽（神聖石/混沌石） | 近黑 L≈6 | 白/亮 L 高至 245 | BrightOnDark，阈值宽松 |

掩码设计：亮度主导 + 轻微暖色容忍（文字 r≥g≥b），不需要 POE Alarm 的蓝色优势判据。
两张表 + 两个名称槽可共用同一掩码参数，指纹/行带管线直接复用。

## 几何
- 全图 2560×1440。面板标题 通貨交換 中心 ≈ (1280, 177)。
- 可用交易表体数据行起于 y≈290；競爭交易表体 ≈ y520+（弹窗式，随行数伸缩）。
- **x≈1230 有贯穿表体的黑色竖分隔线（比率|庫存 列界）**，可作列锚点，替代"最大间隙推断"。
- 数据行文字高 ≈16-20px，行距待多样本行带投影确认（下一步脚本量 24 张全量）。
- 表格弹窗 x 范围 ≈1150-1450；名称槽：需要侧 ≈x838-1088 y307-343，拥有侧对称。

## 24 张全量行带扫描结论（亮字掩码 L≥140 且 r≥g≥b-10，扫描区 x1100-1520 y200-900）

**正常盘口（15 张，结构完全一致）**：
- 数据行：**文字高 ≈17px，行距 ≈30-31px**；两表各最多 6 行，最多 12 条数据行 ✓
- 表头带（可用交易标题+比率/庫存副标 merge）h≈25-26；两表间隔 pitch≈60（含 競爭交易 标题带 h1+h6）
- 比率|庫存 黑色竖分隔线 x≈1230-1240；比率在左、库存在右，数据行两侧都有亮字

**难例（3 张：04.58.50 / 06.45.46 / 07.25.98）**：出现 h=47/66/81 的合并大带、pitch 46-68
——正是**换行小数把相邻行带黏连**的实锤样本，rows.rs 的换行认领逻辑用它们做测试。

**负例（6 张）**：
- 06.59.08 / 07.03.59 / 07.17.98：two-sided=0，扫描区内无数据行（面板被挤偏/选择器打开）→ 正确行为 = 跳帧 ✓
- 07.35.34 / 07.41.63 / 08.08.22：大量碎带 + h=92/105 亮斑（tooltip/其他 UI 遮挡）→ 行带形状完全不像数据行，几何门就能拒绝

**行分类策略（写进 rows.rs）**：不靠"两侧有字"区分表头与数据行（比率/庫存 表头也两侧有字）。
改为：对每带的左格跑比率语法（`^(<|>)?\d+(\.\d+)?:\d+(\.\d+)?$`），语法失败但命中
{比率,庫存,可用交易,競爭交易} 词表的带 = 表头锚点，用它切分 available/competing 段；
h≈2×行距的带或紧贴数据带下缘的短续带走换行认领；其余不合几何的带整帧跳过。

## 初版 LayoutProfile 常量（poe2-zh-TW @2560×1440，供 profiles/poe2_zhtw.rs）
```
ROW_TEXT_HEIGHT   ≈ 17 px   (容差 14-20)
ROW_PITCH         ≈ 30-31 px
TABLE_GAP_PITCH   ≈ 60 px   (available 末行 → competing 首行)
COLUMN_DIVIDER_X  ≈ 1230-1240 (黑色竖线，动态检测而非硬编码)
MAX_DATA_ROWS     = 12 (6+6)
```
用户校准 3 个 ROI（不含图标）：需要名称 / 拥有名称 / 12 行表区。
面板会被仓库/角色面板挤偏——只按居中位置校准，偏移帧靠锚点/身份门自然跳过。

## 弹窗位置形态（实机确证 2026-08-15）
比率表弹窗需悬停市場比率+Alt 才显示，且有离散形态：
- **高位（常规）**：先悬停、后按 Alt——弹窗盖住市場比率区。语料 15 张正常帧 = 高位，首行带 top=60。所有识别按高位标定。
- **低位（bug 形态）**：先按住 Alt、后移动悬停——弹窗出现在市場比率下方（整体下移 ~70px）。当前按 LeadOutOfWindow 防御性跳过（用户默认用法为高位；低位主要出现在 Alt+Tab 截图工作流中）。
- **悬停预览（无 Alt）**：单表、无标题，市場比率正下方（语料 04.08.21）。无竞争表，跳过即正确。

## 已知待办（实机第三轮）
- 左旋/右旋抹除之兆 类一字之差近邻：target-support 双强支持→按规则弃权（防错设计生效，但该类对名字解析成功率低）。方向：近邻决胜阈值或图标缓存。
- 换行小数帧：**用户裁定不深究（2026-08-15）**——部分行数据足以探出套利边、驱动关注决策；继续堆 OCR 规则有复杂度/性能/回归隐患，收益不确定。现状（换行行及其黏连邻行跳过、其余行正常收取、零错误接受）即为设计终态。MergedBand raw 证据保留在案，未来若有低风险方案再议。
- 实测确认：微库存行（1/2/3/7）经 PP-OCRv5 后备全部正确捕获；两条 12/12 满行 ACCEPT 与面板逐位一致。
