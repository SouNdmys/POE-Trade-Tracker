# POE Trade Tracker · UI 设计决策记录

对照施工用。**只记已拍板的东西**；待定项集中在最后一节，定了就搬上来。
所有颜色最终要落到 `crates/ptt-app/src/theme.rs`，组件形状落到 `crates/ptt-app/src/ui.rs`。

版本：v0.3（2026-08-27）· 主题定 A · 浮窗定稿 · 浅色对位定稿

---

## 0. 硬约束（不可协商）

来自使用场景，任何方案都不能违反：

1. **Rust + GPUI 原生桌面应用**，不是网页。不用任何依赖浏览器的效果：
   无毛玻璃/backdrop-filter、无 CSS 动画曲线、无阴影堆叠、无渐变大面积铺底。
   可用的只有：实色填充、1px 描边、圆角、整体不透明度、简单线性渐变。
2. **表格行高固定**。不做行内展开、手风琴、悬浮卡片。看细节 = 右侧明细栏。
3. **界面只出现中文**（用户拍板）。通货名保留游戏客户端原文（繁体，如「神聖石」
   「右旋廢止之兆」）。`i18n.rs` 的英文目录保留给 English 界面语言，不在中文界面混排。
4. **使用场景是游戏中瞟一眼**。可读性 > 氛围感。信息密度服从"一眼扫到重点"。
5. **红 / 黄 / 绿 已被数据新鲜度占用**（绿=新鲜、黄=偏旧、红=过期），语义不可改，
   主题强调色不得占用这三个色相。

## 1. 已定的全局规则

### 1.1 色块＝语义，色字＝主题

这是解决"强调色和三档语义打架"的总规则：

- **实心色块（圆点、徽章描边、左边框条）只表达语义**：绿/黄/红 三档新鲜度、
  琥珀=需要注意、砖红=错误或命中。
- **彩色文字只表达主题**：数值、当前页签、选中行标记用主题强调色。
- 三档语义**永远带汉字**（新鲜 / 偏旧 / 过期），颜色只是加速识别，不单独表意。
  色弱、以及缩到迷你浮窗时，仍然读得出来。

术语：让程序采集一对通货的动作统一叫「**抓**」——下一步去抓 / 排队去抓 / 待抓 N。
不用「翻」（动作是让程序抓一帧，不是翻找）。

### 两个方案各自的风险（选之前先知道）

- **A 的风险**：金 `#D9B978` 与"偏旧"的琥珀 `#E08A3C` 同属暖色区。已用两招压住：
  金只作**文字**、琥珀只作**色块+汉字**；且琥珀刻意偏橙（色相拉到 60° 附近），

- **B 的风险**：铜绿本身是绿。已把强调色推到**青蓝一侧**（色相 ≈ 195°），
  语义绿保持叶绿（色相 ≈ 145°），两者相距 50°。但这也意味着 B 版和旧版墨青
  （`#0E6A64`）在色相上是近亲——如果你讨厌的正是那股青味，B 版会重演。

## 3. 雷达页（已改的排版，两版一致）

| 改动 | 之前 | 现在 |
|---|---|---|
| 扫描摘要 | 3 行流水账句子 | 一条 34px 事实带：起点 / 目标 / 可定价 / 缺价 / 闭环 / 门槛 |
| 新鲜度列 | 倒数第 2 列 | **第 1 列**（用户第一眼要看的东西） |
| 可执行性 / 风险 | 表内两列（80 + 90px） | 撤出表格进明细栏：稀薄期全表同值、充足期大多为空，一列同值没有信息量；170px 还给路径列 |
| 种类 | 「最优兑换 / 闭环」 | 「兑换 / 闭环」（2 字，省 40px 给路径列） |
| 明细栏 | 全是等宽键值行 | 「整条收益 68.86%」升为 15px 主数字，其余降级 |
| 待采集队列 | 页脚散排文字 | 固定 46px 底栏，超出折成 +N |

### 列宽预算（1280 窗口，表宽 842，内容 822）

`数据 54 | 种类 42 | 路径 518 | 收益 62 | 流动性 58 | 汇率 88`（可执行性、风险两列已撤，见上表）

路径列定在 **348px**：最长的五段闭环（混沌石→右旋廢止之兆→神聖石→
右旋抹除之兆→混沌石）实测 328.5px，336px 时会把末尾那一段截掉——
闭环行截掉末段就看不出它闭没闭，所以从可执行性列匀 12px 过来
（98→80，「数据不够」徽章实际只占 56px）。再长的路径才允许截断，
截断优于换行——行高固定是硬约束。

选中行用 `border-left:2px` + 左内边距 8px（其他行 10px），内容盒宽度与普通行
完全一致，**列宽一个字都不得改**——改了右对齐的数字就会错位 2px。

> 这条适用于**每一张表**（雷达、市场分析、关注列表……）。写选中行时容易“把第一列减 2px
> 抵掉边框”，那会把后面所有列一起向左推 2px。正确做法：**只改最后一列**（留给 `1fr` 吸掉）。

### 两个页签：交易所雷达 / 抓取雷达（2026-09-02）

标题行里放两枚页签 chip（当前段金字 + 2px 金下划线，同设置页分段栏语汇），
两段**共用同一张表和同一个明细栏**，切段只是换行（`sync_radar_table` 按段取行，
选中行按路线身份重映射，切段自然清空）。默认停在抓取雷达。

交易所雷达段的差异只有三处：

- 事实带：起点 / 数据小时（落后 N 小时，>2 变琥珀）/ 资产 / 市场 / 闭环 / 有得赚 / 门槛；
- 常驻一条注意条「按官方小时成交均价算的环，不看挂单库存——是去抓的线索，不是可执行的承诺」；
- 明细栏的「排队去抓」换成「去抓这组」：把整条环的每一腿钉进待抓队列（sticky），
  全钉上后显示「已排队 M 腿」+「移除」。

不可用时（没配联赛 / 24 小时没成交 / 结算通货没成交）标题行和页签条照画，
只把表换成一句原因——不然切不回去。

## 4. 浮窗 HUD（已定稿）

两档，热键切换。全部由实心矩形 + 文字构成，`FillRect`/`FrameRect`/`DrawTextW` 直接能画，
不需要圆角、阴影、渐变。文件：`crates/ptt-platform-win/src/win32/hud.rs`。

### 两档尺寸

| 档 | 尺寸 | 回答的问题 |
|---|---|---|
| 迷你 | **260×88** | 识别还活着吗？刚才那帧成了吗？ |
| 展开 | **420×210**（原 420×310） | 上面那两个问题 + 十二行报价原样 |

这两个数字直接对应 `crates/ptt-app/src/shell/mod.rs` 的 `HUD_SIZE`；
旁边那个测试算的是“画笔能堆几行”，高度写小了会静默截掉最底一行，改的时候一并看。

### 展开档结构（从上到下）

```
□ 左侧 2px 竖条：金 = 在跑，红 = 停了。全卡唯一会变色的大色块
 26px  ● 监视中   混沌石 → 削切之兆              #41
  1px  分隔线
137px  可用 6 行（左）  |  竞争 6 行（右）  各 186px
       = 上边距 6 + 栏头 16 + 6×18 行 + 聚合行 hairline 1+2 + 下边距 4
       每行：序号 14px | 比率 flex | 库存 右对齐
       第 6 行（及更差）上方一条 hairline，文本原样保留 <1:75 / >1:60
  1px  分隔线
 24px  ● 结论一句人话                106ms · 已接受 41 · 跳过 566
  1px  分隔线
 20px  待抓  混沌石 → 高階混沌石  缺正向报价            +2
──────
210px  合计
```

迷你档 88 = 上下内边距 5+5 + 状态 20 + 通货对 20 + 结论 20 + 待抓 18。

### 为什么左右两栏

上下排要 12 行×17px；左右排只要 6 行，高度砍掉三分之一，遮住的游戏画面更少。
顺带把**两侧队首价放到了相邻位置**，价差一眼就出来（原来要跨 6 行去比）。

### 用词：拄游戏面板，不拄代码

`available` / `competing` → **可用 / 竞争**；列名用 **比率 / 库存**——
这是游戏自己面板上的词（「可用交易」「竞爭交易」「比率」「庫存」），
玩家不需要在两套词汇之间做翻译。英文界面下照旧用 available / competing。

### 三个状态

| 状态 | 左竖条 | 结论行 | 十二行数字 |
|---|---|---|---|
| 正常 | 金 | ● 绿「12 行全部读到」 | 正常色 |
| 跳过 | 金 | ● 黄「跳过 · 两次读取不一致」+ 2px 琥珀左条 | **整体降一档灰** |
| 故障 | 红 | ● 红「OCR 不可用」 | 整体降一档灰 |

跳过时数字不抹掉（你可能正需要它），但不允许它装成刚读到的。
迷你档同理：通货对那一行降灰 + 右侧标「8s 前」。

### 摆放与不透明度（新增）

平台层已经有一半：`HudInteractionMode::Placement`（拿掉 `WS_EX_TRANSPARENT`，整卡
变拖动把手）、`HudPlacement::Manual { relative_x, relative_y }`、`take_user_move()`
（`WM_EXITSIZEMOVE` 里记下拖完的位置）。缺的是入口、顶条、以及持久化。

**摆放模式**：卡顶多出一条 **22px 顶条**（只此模式可见），外框由 1px 灰变 1px 金
—— 提醒它现在吃鼠标。顶条内容：`拖动摆放 | 不透明 [████████░░] 85% | 迷你 | 完成`。
入口：设置页「摆放…」按钮，或 `Alt+F11` 长按。点「完成」写回设置并回到点击穿透。

**不透明度**：`SetLayeredWindowAttributes` 的 `LWA_ALPHA`，整窗一档，改完立即生效，
不需重建窗口。现在的常量 `HUD_ALPHA = 216`（≨85%）改成设置项，
范围 **60% – 100%，步长 5%**。下限定在 60% 是因为再低 10px 的灰字就糊了（见 `3b`）。

**实现坑**：`WM_NCHITTEST` 现在整卡返回 `HTCAPTION`，顶条上的按钮会点不到。
命中「迷你 / 完成 / 不透明度条」这几个矩形时返回 `HTCLIENT`，在 `WM_LBUTTONUP`
里按矩形分派；其余区域继续 `HTCAPTION` 整卡拖。

**要新增的设置字段**（`ptt-settings`，现在只存了热键）：
档位（迷你/展开）、不透明度、`HudPlacement`（自动 / 手动 + 相对坐标）。
位置存**相对比例**不存像素，换分辨率/换显示器不会飞到屏幕外（`resolve_hud_position` 已实现）。

### 待抓提醒条（接关注列表的建议）

数据源：`ptt_workflows::ProbeCandidate`（通货对 + `ProbeReason` + `ProbePriority`）——
就是关注列表 / 监视器页那份「待采集队列」。注意 `ProbePriority` 声明顺序是
`High, Medium, Low` 且 derive `Ord`，**High 是最小值**，升序取第一条就是最紧的。

规矩（故意可怜，不能抢注意力）：

- 固定 20px，永远在最底，两档都有。
- **只显示最紧的 1 条**，其余折成 `+N`。
- 字号 10–11.5px、meta 灰，**不给颜色、不给按钮**。它是提醒，不是待办。
- 队列空了整条消失，浮窗自动矮 20px。
- 排队/移除这类操作不上浮窗（浮窗是点击穿透的），只在主窗口做。

热键（现有默认值，则例里照写）：监视开关 `Ctrl+Alt+F10`、浮窗开关 `Alt+F11`、
手动抓一帧 `Alt+F12`。

## 4. 监视器页（已定稿，见 `4a`）

落地页。三层，按用户的三件事排：

| 区块 | 高度 | 回答 |
|---|---|---|
| 健康带 | 56px 通栏 | 数据是不是活的 |
| 最近盘口 | 固定（可用/竞争左右各 6 行×28px） | 刚才读到什么 |
| 这个盘口能怎么赚 | 左栏 flex | 有没有得赚 |
| 下一步去抓 | 右栏 flex | 接下来翻哪对 |
| 跳过原因 | 右栏 132px | 不正常的话为什么 |

### 健康带（新增）

`4px 左色条（新鲜度三色） | ● 数据新鲜 · 最近一帧 71s 前 | 已接受 41 | 单帧 106ms | 跳过 17`

关键一条：**「已跳过 566」必须拆开**。549 帧是 `not-book-view`（面板没开着），
那是正常待机；真正需要留意的只有 17 帧。把待机当错误报，会训练用户忽略所有警告。

### 要修的 bug

`skip_label()` 没有 `not-book-view` 分支，落到 `other => other.to_owned()`，
所以界面上直接显示英文 key——而它是出现次数最多的一条。
补成「面板没开着」，并在统计里归为「正常待机」单独计数。

### 「机会」面板：句子 → 表格

原来是四行英文流水账（`100 divine-orb -> omen-of-dextral-annulment: direct 10 | best 15 (3 hops, risks ...)`）。
改成列：种类 / 路径 / 直兑 / 最优 / 收益，风险另起一行徽章（超过 3 条折成「还有 N 条」）。
这要求 `AcceptedBook::analysis` 从 `Vec<String>` 改成结构体——句子拼好就拆不回来了。

**负数用砦红文字**（-26.00%）。这是「色字＝主题」规则的唯一例外，
因为负数用红是跟金融界面学的，而且它不是色块，不会和新鲜度红点混。

## 5. 关注列表页（已定稿，见 `5a`）

左栏 716px（关注列表）+ 右栏 flex（覆盖与缺口）。

### 新增：「忽略」一对通货

用户原话：“系统推荐的不重要的通货对一直挂在那里，我不想抓也占着提醒位置”。

- 「下一步去抓」（原「待采集队列」）每行右侧加 **忽略**。
- 点了之后这一对**同时从三处消失**：关注列表页、监视器页「下一步去抓」、游戏浮窗底条。
- **永久生效**，不会因为又缺一次数据自己冒回来。
- 底部固定一行「已忽略 N 对 · 查看并恢复」——唯一的后悔药，不藏进设置页。

**存哪里：三个列表，别合并。** 仓里已经有两个，新增第三个：

| 动作 | 含义 | 存储 |
|---|---|---|
| 隐藏 | 不看这行估值（纯显示） | `MarketTuning::hidden_assets`（已有） |
| 忽略建议 | 别再推荐我关注这个通货 | `ignored_suggestions`（已有） |
| **忽略去抓** | **这一对我不抓** | **`ignored_probes`（新增，存通货对而非单个通货）** |

三件事含义不同，合成一个会静默改变引擎允许做的事（仓里 `ignore_suggestion` 的注释
已经为同一件事论证过一次：“别问我这个” ≠ “永不路过这个”）。

### 其他改动

- **88 个角色按钮 → 22 个下拉**。原来每行 4 个按钮（目标/桥梁/仅观察/不关注）铺满整页；
  现在只显示当前角色，点开才是四选一。行高仍固定 28px。

## 7. 兑换页（定稿 = `11a`；`9a` 已作废）

### 路线可以多段（`9a` 的错）

「中转」写成一个通货名，等于默认只中转一次。程序的**最大跳数 = 3**，一条路线
可以有两个中转（监视器那句「best 15（3 hops）」就是三段）。修法：

- **路线列铺全路径**，截断优于换行；旁边加**步数**列（1/2/3），可排可筛。
- 选中一行 → 右上**路线明细**：每一段的汇率、进去多少出来多少、这一段吃得下多少，
  并标出**卡点**那一段（`walk.pinch()`）。挂单策略压到右下 164px。
- 表尾写明定义：**「能吃下」取全路径最窄的那一段**，不是第一段的深度。

### 最优汇率 ≠ 做得完

三段那条 +78.9% 只吃得下 14，两段的 +75.1% 吃得下 63。
工具栏因此有「按汇率 / 按吃得下的量」两种排序，结论带直接把这句话说出来。

### 不再抄三遍

原页把**同一批 14 条路线按 1 / 10 / 100 三种规模各列一遍**，一屏 45 行，
行与行之间只有末尾那个数不同。现在只按用户填的持仓算一遍；换规模就改那个数。
（兑换规模的调参项已删除：没填持仓时按内置 1 / 10 / 100 档报价，不再是三个并列区块。）

### 深度条是这页的主角

每行末尾那句「这个汇率上市面能吃下 63 神聖石」→ 一根 110px 深度条 + 数字 + `/ 100`。

- 条满＝吃得下你全部；琥珀＝部分；砦红＝远远不够。
- 理由：14 条路线的汇率只差 5%，**深度却差 100 倍**（6 vs 727）。
  真正决定走哪条的是深度，不是汇率。
- 「少于你要推的量」那个红框徽章删了——深度条已经把它画出来了。

顶部结论带：「100 神聖石 → 理论上最多 19 · 比直兑多 9 · 但最好那条只吃得下 14」。

### 右栏：挂单策略

三档保留（压一档 / 跟价 / 贪婪），**每档配一句代价**：最快成交 / 排在原单之后 /
可能挂到天亮。原来只有百分比，看不出为什么不总选最贪的那档。
「要等人吃单」那三个按钮去掉——它们不触发任何操作，只是标签。

## 11. 浅色主题（已定稿）

深色仍是默认，也仍是设计基准——§2 方案 A 的值一个没动。浅色是**同一套语义的对位**，
不是第二套设计：槽位、层级顺序、「色块＝语义 / 色字＝主题」的总规则全部照抄，
只有明暗关系整个翻过来。

存在设置里（`AppSettings::ui_theme`），**不跟系统日夜走**——这个工具是叠在游戏窗口
旁边用的，亮暗该由用户按当时的游戏画面定，不该由操作系统的日夜设置替他定。

### 11.1 颜色改成运行期查表，但调用点一个字没改

`RAIL` 这类名字从「一个颜色」变成「一个**槽位**」（`Token`），`c()` 拿槽位去当前
调色板查值。页面代码写的还是 `c(RAIL)`，形状和以前完全一样。

**为什么不把 `cx` 传进去。** 正规做法是 `c(cx, RAIL)`，从 GPUI 的全局状态里取主题。
但 ptt-app 里有 **436 处 `c(...)` 加 23 处 `hsla_of(...)`**（theme.rs 自己那 90 处不算），
改签名就是四百多处逐一改写；更麻烦的是其中相当一部分坐在 builder 闭包里，
那个位置手上根本没有 `&App` 可拿，得先把 `cx` 一层层捅进去才谈得上调用。
所以换成另一条路：生效的调色板存成一个进程级的原子字节（`ACTIVE_MODE`），`c()` 自己去读。

代价写明：**一个进程只有一套皮肤**，做不到两个窗口一深一浅。本工具只有一个主窗口，
这个代价收得起；哪天要做多窗口，这条得先推翻。

**默认是深色**，于是组件画廊 `ptt-ui-preview` 不必读设置也能跑——它只调
`apply_app_theme`，拿到的就是深色。同理，启动时 `restore_saved_palette()` 必须排在
`apply_app_theme()` **之前**：反过来的话，选了浅色的人每次启动都会先闪一帧深色。

**一个坑记在这里**：运行期换肤不能用上游的 `Theme::change`。它会顺手 `apply_config`，
把字体、字号、圆角、阴影连同一百多个颜色字段一起推回 gpui-component 的默认值——
整套设计系统当场消失。只能自己重抄一遍（见 `AppShell::set_theme`）。

### 11.3 `SELECTED` 为什么必须裂成两个

一个值干不了两份工，这是浅色逼出来的：

- **实底**：选中行的背景，上面要压得住 `TEXT_PRIMARY` 的黑字。
- **淡染**：喂给 `list_active` / `table_active`，上游把它画在行**上面**（绝对定位块）
  而不是行背后，所以必须夹到 20% 透明，否则整行文字被盖掉。

浅色下这两个岗位互相排斥。`#D8E6F8` 当实底很好（黑字 13.5:1），可它压到 20%
铺在白 panel 上算出来是 `#F7FAFE`，和 panel 只差 **1.05:1**——等于什么也没画，
选中行看不出来。换成深得多的 `#5A8BC8` 做淡染才有 1.24:1，而这个蓝当实底又会把黑字埋掉。

**深色两个槽位取同一个十六进制值**（都是 `#232B3A`），所以这次拆分**没有改动深色的任何一个像素**。
拆的是浅色的需要，不是深色的债。

### 11.4 能算出来的红线，两套都量

调色板是「看着还行」最容易蒙混过关的地方，所以给它几条能算出来的红线，
守在 `theme.rs` 底部的测试里。实测值：

| 尺 | 深色 | 浅色 | 门槛 |
|---|---|---|---|
| `TEXT_PRIMARY` 对 `PANEL` | **14.2 : 1** | **17.1 : 1** | ≥ 7 : 1（WCAG AAA 正文） |
| `TEXT_SECONDARY` 对 `PANEL` | **8.0 : 1** | **8.0 : 1** | ≥ 4.5 : 1（AA） |
| `TEXT_META` 对 `PANEL` / `RAIL` / `RAIL_DEEP` | **4.4 / 4.1 / 4.5 : 1** | **6.0 / 5.4 / 4.6 : 1** | ≥ 4.0 : 1 |
| 金 `ACCENT` 与琥珀 `WARN` 的色相距 | **11.7°** | **14.1°** | ≥ 10° |
| 琥珀 `WARN` 与砖红 `DANGER` 的色相距 | **23.6°** | **22.9°** | ≥ 10° |
| 金 `ACCENT` 与砖红 `DANGER` 的色相距 | **35.2°** | **36.9°** | ≥ 10° |

色相那三条是给 §2「A 的风险」上的锁：金、琥珀、砖红同属暖区，压住它的两招
（金只作文字、语义色只作色块＋汉字）之外还要加一道**色相距离**，免得后人调色时
把任意一个往另一个推。三对两两都量，是因为只量金/琥珀那一对时，「把琥珀往红橙
推来拉开金」看起来像个改进——实际是解开一对、撞上另一对（见 §11.8）。

`TEXT_META` 那条的门槛是 4.0 而不是 AA 的 4.5：深色版在 panel 上本来就是 4.4，
这条守的是「别比现有的更糊」，不是给一个从来没达过 AA 的层级补票。

**两套都测，不只测「当前生效的那一套」。** 只测生效的那套等于把另一套放生，
而放生的那套照样会发到用户手上——浅色调色板刚加进来的时候就是这么无人看守的。
同理还有一条「浅色不是深色的复制粘贴」：42 个槽位逐个比，两套取值相同就报错
（`SELECTED` / `SELECTED_WASH` 在深色里相同是**槽位之间**相同，不违反这条）。

### 11.5 浮窗 HUD 不跟着变（有意）

两档浮窗（§4）在两套主题下**都保持深色**。两条理由，任一条单独成立：

1. 它浮在**游戏画面**上，不是浮在本程序的界面上。POE2 客户端是暗的，
   一张浅色卡片贴在上面是一块刺眼的白斑——浮窗的深色配的是游戏，不是主窗口。
2. 依赖方向不允许。ptt-app **依赖** ptt-platform-win，`hud.rs` 读不到 `theme.rs`
   （反过来引用就成环了）。

代价是 `crates/ptt-platform-win/src/win32/hud.rs` 里那十几个 `hud_rgb(...)` 是
§2 定稿值的**手抄副本**。动深色调色板时顺手对照一遍，它不会自己跟上。

### 11.6 已知瑕疵：拉伸窗口时边缘闪一下黑

拉大主窗口时，新露出来的那一条在下一帧画上来之前是**纯黑**的。原因在上游：
gpui 注册窗口类时把 `hbrBackground` 写死成 `CreateSolidBrush(COLORREF(0))`
（`gpui-0.2.2/src/platform/windows/window.rs`），那把刷子填的就是这条缝。

深色下它和 canvas `#12151B` 几乎看不出来，浅色下是一条黑边闪一下。纯观感问题，
不影响任何读数，且改不了（在上游、且是进程级窗口类）。记一笔，别当成新 bug 再查一遍。

### 11.7 评审改出来的四处（浅色专有的坑）

浅色版实装后过了一轮完备性评审，抓到的都不是「编译不过」，而是「切过去才看得见」。
记在这里，因为这一类问题有共同的形状：**同一个值在深色下是对的，在浅色下语义翻转。**

1. **趋势列的「持平」比「涨跌」还响。** 迷你曲线的持平填充原来借 `RAIL_DEEP`——
   深色里它比面板暗一丁点，几乎看不见，正合「一半的行都持平，全上色就没重点了」；
   浅色里同一个值是白底上的一块中灰，比金色的「涨」和红色的「跌」都抢眼，整列的
   轻重颠倒。拆出 `TREND_FLAT_FILL`：深色取原值（不动一个像素），浅色取
   `#F4F6FA`，保住「三种填充里最轻的那个」这层相对关系。
2. **注意条的标签用错了琥珀的那一半。** `warning_band` 的 10px 标签原来用块色
   `WARN`，浅色底上只有 3.7:1——一个存在意义就是要被看见的组件最先糊。改用字色
   `WARN_TEXT`（浅色 5.6:1，深色也从 6.4 提到 7.9）。和 `SELECTED` 裂成两个是
   同一回事：块色和字色是一对，别混用。
3. **`TEXT_META` 没人量过。** 它是全 app 出现最多的文字色，而且落在三种底上
   （panel / rail / rail_deep），尺子却只量 panel。浅色第一版在 rail_deep 上是
   3.9:1，深色同样位置有 4.5:1——最常出现的那一层恰好是唯一回归的那一层。
   `TEXT_META` 压到 `#5A6472`，尺子扩到三种底。
4. **校准页的框画在游戏截图上。** 那几个框和放大镜十字线的背景不是我们的面板，
   是 POE 的近黑客户端——而它不会因为用户切了浅色就变亮。浅色的强调色是为白底
   调的，贴到近黑上就不够亮。和 §11.5 浮窗留深色是同一条理由，只是 §11.5 当时
   没把校准页算进来。**做法后来改过**：最初是一个 `c_over_game()` 函数硬取深色
   皮肤的值，现在是三个正式槽位（`OVER_GAME_ACCENT` / `OVER_GAME_DANGER` /
   `OVER_GAME_GUIDE`），每套皮肤各自声明"画在游戏上用哪个值"——浅色用的是提亮
   过的墨蓝 `#8FB6E8`（近黑上 9.0:1），而不是深色皮肤的金。理由见 §11.9 末尾。

### 11.8 浅色下明暗这条线索是失去的（已知、无解、有替代）

深色版里金是整套中**最亮**的（相对亮度 0.51，三个语义色分别是 0.34 / 0.20 / 0.14），
所以金点和琥珀点摆在一起，不必先分辨色相，亮度差就够了——两者亮度比 1.48。

浅色下这条线索没了。四个颜色都必须够暗才能在白底上读出来，于是全被压进同一条窄
亮度带，金/琥珀的亮度比掉到 1.21。试过两个方向，都是**解开一对、撞上另一对**：

- 把琥珀往红橙推（评审给的处方）：金/琥珀好转，但琥珀/砖红从 1.52 掉到 1.27。
- 把金压暗：先撞上琥珀（`#A07817` 处比值 1.02，几乎同亮），再撞上砖红。

根因是三个语义色已经占住了那条带，金无处可去——除非暗到砖红以下，那就不是金了。
所以浅色下这道防线只剩两条，都还在：**色相拉开**（三对两两 ≥ 10°，由
`the_warm_hues_stay_apart_in_both_palettes` 锁死），以及**语义色永远带汉字**
（总规则，见 §2 开头）。色块只是加速识别，从来不是唯一信号。

**后记**：这一节描述的困境最终以"浅色退出金色家族"收场（见 §11.9）——
强调色换成墨蓝后,浅色下的暖区只剩琥珀和砖红两个语义色,它们之间 22.9° 的
色相距离本来就够。深色主题不变,这一节对深色仍然成立。

### 11.9 浅色不用金:两轮黄的失败与换色相的裁定

浅色的强调色最终是**石板墨蓝 `#3D6CA5`**,不是金(初定 `#2E5A8F`,用户嫌
填充上的字看不清,又调淡一档;`ACCENT_TEXT` 仍用较深的那支)。这是两轮失败之后用户在
四个候选(现状青铜 / 墨蓝 / 黛青 / 石墨)里当面拍板的,记下过程免得后人再走
一遍:

1. **第一版:中段金 `#AC821F`。** 白底上的中段黄就是芥末,满屏土黄,实机
   一看即弃。教训:黄在白底上只有"很浅"和"很深"两个可用区间。
2. **第二版:深青铜墨 `#7E5D0F`。** 对比度全达标(白底 6:1,三态字底
   5.8/4.8/7.4),纸面上的推导无懈可击——实机还是被判"屎色"。教训:
   **可读性挡不住色貌**,深橄榄在白底上仍读作黄褐,而黄褐没有让人舒服的档位。
3. **裁定:换色相。** 深色主题的金从没被抱怨过(深底上的金是发光感),浅色
   单独换。墨蓝与浅色底色同族(整套浅色本来就是石板灰蓝调),是"纸上蓝墨";
   红利是金/琥珀相撞(§11.8)在浅色下彻底消失——accent 离暖区 185°。

代价一条:浅色下"选中/命中"的蓝家族(`SELECTED`/`SELECTED_WASH`)和强调色
同族了。实机看是协调而不是混淆——选中行=淡蓝底+墨蓝左条,本来就该是一件事。

守卫照旧:三态字底 ≥4.5(墨蓝三态 5.4/6.5/8.1,hover/按下往深走,实机
又按用户反馈调淡过一档)、色相距离、五级文字对比,
全部两套皮肤各测。

**换完色相之后的清扫**:把强调色从金换成蓝,会留下一批"说自己是金"的尾巴。
清过一遍(全仓穷举 + 逐像素核验),分三类处置:

- **图例文案不再点名颜色**。`金框 = 你框好的`、`金条 = 已排队`、
  `金 = 变贵` 三处都在说一个已经不成立的颜色;旁边本来就有色块/色条,
  由它自己说,文字只说含义。
- **画在游戏上的三个槽位**(见 §11.7 第 4 条)。浅色用提亮墨蓝 `#8FB6E8`,
  预设参考框用更安静的 `#646D7A`——它是"提示"不是"你框的",亮度必须
  压在框之下,这条也有守卫测试(上界 <4.5:1、下界 ≥2.5:1)。
- **注意条的正文改中性色**。四个页面的 `notes` 原来是一整段琥珀字——琥珀是
  **块**色,整段染色既违规又吓人(首次运行"报表窗口里没有数据"这种纯提示也
  被涂成警告)。现在统一走 `warning_band`:wash 底 + 2px 琥珀左条 + 短标签
  承担语义,正文中性。

清扫后逐像素核验:浅色画面里剩下的暖色像素全部属于语义琥珀/红(chip 描边、
新鲜度圆点),深色皮肤的金只剩标题栏那个 16×16 的 .ico 图标——那是系统画的,
不是界面。

### 11.10 画廊可以看浅色

`ptt-ui-preview` 没有设置文件可读，默认深色。加环境变量看浅色：

```
PTT_LIGHT=1 cargo run --bin ptt-ui-preview
```

这不是可有可无的：§11.7 那四条全是**逐个组件摆在一起看**才会发现的，而画廊是
唯一能这么看的地方。改完调色板，两套都过一遍画廊。

### 11.11 窗口标题栏跟的是系统，不是本程序

主窗口用的是 Windows 自己的标题栏（`TitlebarOptions` 未开 `appears_transparent`），
而 gpui 按**操作系统**的亮暗设置调 `configure_dwm_dark_mode`。于是系统深色 + 程序
浅色的组合下，白色界面顶上会顶着一条黑标题栏。改不了，除非自绘标题栏。

连带一笔：`TITLEBAR` / `TITLEBAR_TEXT` / `TITLEBAR_BORDER` 三个 token 和
`colors.title_bar*` 都写了值但**当前无人渲染**（app 没有用 `gpui_component::TitleBar`）。
§11.2 的表里照样列着它们的浅色值——那是备着的，不是生效的。别为它们不生效去查 bug。

## 14. 交易所页（八测后定稿）

官方交易所成交史那一页（不是兑换页）。八测反馈：整页清一色灰、抓不到重点，
柱状走势看不出方向。

### 列宽

名称 210 · 价值 110 · 涨跌 80 · 走势 110 · 成交 / 深度各一格 · 放量 chip · 对手。
**表头和行是两处各写一遍的宽度，没有常量联动**——改一处必须对照另一处
（`exchange.rs` 里 `head_cell` 与 `data_cell` 两段）。走势列宽用 `SPARK_WIDTH`。

### 涨跌三态色（沿用硬约束 #5）

涨=金、跌=砖红、持平=灰；**绿仍然只给新鲜度**。阈值与市场分析页同值：
`±200 bps`（2%）以内算持平，不上色——一半的行都在这条带里，全上色就没重点。

| 状态 | 曲线线色 | 曲线填充 | 涨跌字色 |
|---|---|---|---|
| 涨 ≥ +2% | `ACCENT` | `ACCENT_FILL` | `ACCENT_TEXT` |
| 跌 ≤ −2% | `DANGER` | `DANGER_WASH` | `DANGER_TEXT` |
| 持平 | `TEXT_DISABLED` | `TREND_FLAT_FILL` | `TEXT_META` |

只有涨跌列和曲线上色。价值 / 成交 / 深度保持灰阶（色字＝主题）；放量 chip 已是琥珀。
关注中的通货，名字后面那个「·」用 `ACCENT_TEXT`——一眼看出哪些是自己的。

### 走势曲线

与市场分析页同一个组件（`ui::sparkline`，110×22 面积曲线，min–max 归一），
不再画柱。数据不足两天画 `day_bars`，不画假曲线（§6 既定裁定）。
历史视角（截至日期）下曲线终点＝截至日，颜色按截至日那天的涨跌算。

### 新面孔条

三种信号里只有「升值」的证据是涨了多少，走上面同一套三态字色；
「放量」「价差」的证据是倍数和偏离，不是涨跌，保持灰阶。

### 明细栏与时段档位（P12 小时账本）

行可选中：`.id("exchange-{id}")`、固定 `H_TABLE_ROW`（28px，以前是 `py_1`）、
`on_mouse_down` 记 `exchange_selected`、选中行 `SELECTED` 底。细节不在行内展开
（硬约束 #2），页面变成"表 + 右侧 300px 明细栏"一行，同市场分析页。

明细栏内容自上而下：`kv_headline` 最新小时价（字色走涨跌三态）、窗口成交额
（`TEXT_DATA`）；`kv_row` 每小时均值；时段档位条（`exchange_range_row`，形状同雷达页
页签：当前档金字 + 2px 金下划线）；`sparkline_sized` 270×56 价格线（线色/填充走
涨跌三态，缺口处断开）；`hour_bars` 270×36 成交柱（`TEXT_DISABLED`，0 和缺口画
1px 底线）；两端本地时刻 `FS_10`/`TEXT_META`；「按时段」按钮切成 24 桶剖面
（柱 `TEXT_GHOST`）+ 峰值时段一行 `ACCENT_TEXT`；最后「窗口内 N 个小时无成交」
`FS_10_5`/`TEXT_META`，0 不显示。绿依旧只给新鲜度。

图表可悬停：鼠标落在哪格，那根柱子换 `TEXT_META`、价格线上落一个 4px 点、竖一条
`TEXT_GHOST` 细线；图下两端时刻那行顶替成读数（`08-27 14:00 · 成交 125k · 价 0.005`，
像素不够并了格就报区间与均价，按时段视图报 `14:00–15:00 · 合计 3.5M`），同一行高，
图不跳。不做跟着鼠标走的浮框，理由同硬约束 #2。线上的点画在格正中，和柱子同一把尺。

表格上方同一排档位 chip（24h / 3d / 7d / 全部保留），切档标脏页面，表按该窗口的
成交额重排；成交列表头带档位（`成交/时 · 24小时`），列里的数是按它算的。
